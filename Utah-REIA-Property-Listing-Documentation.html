Platform Overview

The Utah REIA Marketplace is a web-based platform embedded inside the GoHighLevel (GHL) website. It allows members and guests to browse, list, and inquire about two types of real estate assets:

🏠 Property Listings

Physical real estate properties for sale. Members list their properties; buyers browse and contact sellers directly.
📋 Notes Marketplace

Mortgage notes (performing and non-performing) available for sale or trade. Note sellers list their paper; buyers inquire and negotiate.

Technology Stack

Backend (API)Vercel Serverless Functions (Node.js)Handles all data operations
DatabaseAirtableStores properties, notes, and subscribers
Image StorageCloudinaryHosts listing photos

How It All Connects

User Uploads Image → Vercel API → Cloudinary → URL saved in Airtable
GHL Form Submitted → GHL Webhook → Vercel API → Airtable Subscribers

Property Listings

The property listings tab allows sellers to post properties and buyers to browse, filter, and contact sellers.

What a Seller Can Do

  • Click "List Your Property" to open the listing form
  • Fill in property details: title, price, address, type, beds/baths, description
  • Upload up to 3 photos — images go to Cloudinary, URLs stored in Airtable
  • Submit — the property appears on the marketplace immediately

What a Buyer Can Do

  • Browse the property grid with filtering by type, price, beds, baths, and status
  • Click any property card to open the full detail modal
  • Must accept the Utah REIA Disclaimer & Terms before contacting a seller
  • Fill out and send an inquiry — seller receives an email, buyer gets a confirmation

Managing a Property (Seller Only)

Only the person who listed the property (verified by email) can update or delete it. This prevents anyone else from modifying listings they don't own.

Click Update or Delete → Enter listing email → 6-digit code emailed → Verified → Action allowed

Notes Marketplace

The Notes Marketplace is a dedicated tab alongside Properties. It allows investors to buy and sell mortgage notes — legal documents representing a loan secured by real estate.

What is a Mortgage Note?

A mortgage note is a financial instrument — essentially the IOU on a property loan. Note investors buy these at a discount to earn yield.

Performing Notes

Borrower is making payments on time. Lower risk, lower discount, steadier yield.
Non-Performing Notes

Borrower has defaulted. Higher risk but larger purchase discount and higher potential return.

API Endpoints

All backend logic runs as Vercel Serverless Functions. Each endpoint handles a specific operation and is accessible at https://property-listing-32ax.vercel.app/api/...

Properties

EndpointMethodWhat it does
/api/get-propertiesGETFetches all property listings from Airtable
/api/add-propertyPOSTCreates a new property listing
/api/update-property-statusPOSTUpdates status for a property OR note (pass type:"note" for notes)
/api/delete-propertyPOSTDeletes a property OR note (pass type:"note" for notes)
/api/contact-propertyPOSTSends inquiry email to property seller + confirmation to buyer
/api/upload-imagePOSTUploads image to Cloudinary, returns the secure URL
/api/check-property-expirationPOSTChecks and expires old properties AND notes (runs as daily cron at 9 AM UTC)

Notes

EndpointMethodWhat it does

/api/add-notePOSTCreates a new note listing (also fires subscriber notification)
/api/contact-notePOSTSends inquiry email to note seller + confirmation to buyer

Verification

EndpointMethodWhat it does
/api/send-verification-codePOSTSends a 6-digit code to the seller's email (expires in 10 mins)
/api/verify-codePOSTValidates the 6-digit code entered by the user
/api/get-property-contact-emailGETFetches the contact email stored for a property to verify ownership
/api/get-note-contact-emailGETFetches the contact email stored for a note to verify ownership

Subscribers & Notifications

EndpointMethodWhat it does
/api/subscribePOSTAdds a new subscriber (email, name, phone) to Airtable
/api/notify-subscribersPOSTSends instant email alert for a new property listing
/api/notify-notePOSTSends instant email alert for a new note listing
/api/daily-digestPOSTSends a combined daily digest of all new properties + notes (cron at 4 PM UTC)

Shared endpoints for Properties & Notes: The update-property-status and delete-property endpoints serve both types. For notes, pass "type": "note" in the request body — the endpoint automatically switches to the Notes Airtable credentials. This saves serverless function slots on Vercel.

Email Verification & Security

To prevent anyone from updating or deleting a listing they don't own, a secure email verification flow is required before any management action is permitted.

Verification Flow

1. Click Update or Delete → 2. Enter your email → 3. Email checked vs. Airtable
4. 6-digit code emailed → 5. User enters code → 6. Verified — action proceeds

Security Details

  • Verification code expires in 10 minutes
  • A 60-second cooldown prevents resend spam
  • The code is embedded in a signed HMAC token — cannot be forged
  • The email entered must exactly match the contact email stored in Airtable for that listing
  • Works for both Properties and Notes — separate modals, same backend

Required: The VERIFICATION_SECRET environment variable must be set in Vercel. This is used to sign and validate the HMAC tokens. Use any long random string as the value.

Subscriber Notifications

Subscribers are people who have opted in to receive email alerts when new listings are added to the marketplace.

Three Types of Notification Emails

1. Instant Property Alert

Fires immediately when a new property is listed. Sends a branded email with the property card (image, title, price, specs) to all subscribers via BCC.

2. Instant Note Alert

Fires immediately when a new note is listed. Sends a navy-branded email with the note details (asking price, UPB, performance status, rate, LTV) to all subscribers.

3. Daily Digest (Automatic — 4 PM UTC)

Runs every day via Vercel cron. Fetches all properties AND notes added in the last 24 hours. Sends one combined email with separate sections for each type. Skips sending if nothing new was listed that day.

Listing Expiration System

All listings — both properties and notes — automatically expire after 90 days. This keeps the marketplace current and prevents stale listings from misleading buyers.

Expiration Timeline

Days Since ListedWhat Happens
Day 1 – 75No action taken
Day 76 (14 days before expiry)Warning email sent to the lister. The Expiration Warning Sent checkbox is set to true in Airtable so the warning only fires once.
Day 90+Listing is automatically deleted from Airtable. A deletion notification email is sent to the lister.

How It Runs

Daily Cron — 9:00 AM UTC → Fetches all Properties + Notes → Checks age of each listing → Deletes expired / Warns near-expiry

Both property and note checks run concurrently in the same serverless function, saving on Vercel's function usage limits.

Airtable requirement: Both the Properties table and the Notes table must have a field named exactly Expiration Warning Sent of type Checkbox. Without this field, the warning email will fire every day instead of just once.

GHL Integration

GoHighLevel (GHL) is connected to this system in two ways.

1. The Marketplace Page (Embed)

The entire property and notes marketplace is an HTML page embedded inside GHL as a custom page. Users navigate to it through the Utah REIA website and interact with it directly in the browser.

2. Subscriber Capture via Form Webhook

When a guest fills out the "Property Listing" form on the GHL site, a GHL workflow fires a webhook that automatically saves them as a subscriber in Airtable.

GHL Workflow Configuration

StepSetting
TriggerForm Submitted — Form is "Property Listing"
ActionSend Webhook (Custom Webhook)
MethodPOST
URLhttps://property-listing-32ax.vercel.app/api/subscribe
HeaderContent-Type: application/json

Webhook Body

{ "email": "{{contact.email}}", "name": "{{contact.full_name}}", "phone": "{{contact.phone}}" }

The subscribe endpoint automatically handles duplicates — if the same email submits the form twice, it won't create a duplicate record in Airtable.

Disclosures & Legal Notices

The platform includes four compliance components that appear at key interaction points to protect Utah REIA legally.

1. Acceptance Modal (Registration Gate)

Before a buyer can contact any seller (property or note), they must check two boxes confirming: (a) they agree to the Utah REIA Disclaimer & Terms of Use, and (b) they consent to receive communications. The "Accept & Continue" button remains disabled until both boxes are checked.

2. Wire Fraud Warning Banner

Displayed inside every contact and inquiry modal. Warns buyers never to wire funds based solely on emailed instructions and to always verify bank details by phone directly with a known contact before any transfer.

3. Compact Inline Listing Notice

Shown at the top of every property and note detail modal. Reminds viewers that Utah REIA does not verify listings, is not a broker, lender, or advisor, and that all due diligence is the buyer's responsibility.

4. Listing Page Footer Notice

A persistent notice bar at the bottom of the marketplace page stating that Utah REIA is a marketplace only and is not a party to any transaction. Includes a link to the full legal disclaimer page.

Full Disclaimer URL: https://utahreia.org/property-listing-legal-disclaimer — this page must remain live and accessible at all times as it is referenced in every disclosure component across the platform.
